# 分支、提交与审查

本仓库的默认分支为 `main`。普通变更须先在用途明确的开发分支完成，再经 PR 审查和必需检查，以 squash 合并；禁止直接推送、强制改写或删除受保护分支。远端保护与必需检查以实际 GitHub 配置为准，变更前必须验证规则并保留恢复路径。

## 提交

新增维护者提交以及 PR 标题使用 `type(scope): 简体中文具体变更主题`，其中类型和范围使用稳定英文技术标识。说明必须能辨认实际对象和行为；不能用“优化代码”“修复问题”等空泛主题。网页静态资源、DOM 交互或部署行为变化须记录背景、影响与验证；不兼容变化使用 Conventional Commits 的 `!` 与 `BREAKING CHANGE` 描述契约及迁移。

本地 `commit-msg` 钩子在提交前校验，不能取代远端规则。共享历史不为了修饰消息进行强制重写；最终 squash 消息也必须与交付内容相符。

## PR

每个 PR 对应独立的逻辑交付对象，正文准确列出背景、修改范围、页面行为、兼容和风险、执行过的测试、未完成检查及必要恢复办法。创建前对照已有分支、PR、实际 Diff、授权与提交记录。禁止以纯说明代替实际验证、合并无关改动或虚构成功结论。

## 审查与合并

检查页面渲染、响应式布局、输入和错误路径、链接与可访问性、源文件完整性、许可、提交历史和未解决问题。审查针对准确 HEAD 和文件差异，作者自查不等于独立审查；独立技术审查可以由未参与实现的 Agent 进行，结果应绑定准确 HEAD 并作为独立的检查记录，不得伪装成其他 GitHub 人类账户批准。单账号维护时不得设置作者无法满足的平台审批数量。

全部真实必需检查、必要独立技术审查和阻断问题通过后才能合并。新增提交使受影响的旧审查结果失效。治理工作流及检查器的变更必须额外审查；不得借普通 PR 删除或跳过门禁。

## 执行入口

`.github/scripts/governance_gate.cjs` 为元数据结构校验器；独立技术审查仍需读取实际变更。公开仓库的 `pull_request_target` 事件自 2026-12-02 起默认受 GitHub Actions 事件策略阻断，必须在设置远端必需状态之前将可信工作流加入允许策略，完成同等配置的正例、反例与绕过验证。
